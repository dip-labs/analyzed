# analyzed bench gate: multi-worktree agent load

Benchmarks the shared `analyzed` daemon (this repo, unmodified release build)
under the prod agent workload model: one canonical warmed Rust world, N
concurrent sessions, each session's git worktree expressed as private didOpen
overlays. Decides go/no-go for forking the analyzed glue layer.

## Subject

Any sizable Rust repository. Use a read-only **clone** pinned to a fixed
revision — the harness never touches the original repository.

## Run

```sh
cargo build --release
python3 bench/run_bench.py --subject /tmp/btcr-bench
```

Options: `--scenarios disjoint,same_file,distant_branch,manifest,storm`,
`--cells 1,5,20`, `--iters 10`, `--distant-files 250`, `--out bench/results`.

Python 3.10+ stdlib only. macOS only (uses `ps`, `/usr/bin/sample`).

## Matrix

| scenario | what it models |
|---|---|
| `disjoint` | each session overlays 4 distinct module files — the agent case as agents would actually do it. In analyzed 0.4.2 this attaches NO overlay crate (sync drops identical-to-base cone files, so the crate root never enters the overlay): semantic queries come back empty. Measured as a functional finding. |
| `disjoint_rooted` | same + a session-unique "touch" of the crate root, which pulls the root into the overlay and attaches a per-session overlay crate cone — the only way 0.4.2 gives overlay semantics for module files |
| `same_file` | sessions hold divergent versions of ONE file — the crate root itself, so this is simultaneously the one-path-N-versions worst case and the N-overlay-crates worst case |
| `distant_branch` | sessions carry a big branch diff (250 files, root included) |
| `manifest` | diff touches Cargo.toml (+ root); plus a real-worktree-root probe |
| `storm` | sequential round-robin query/edit interleave (rooted) — view-flip price |

Each scenario runs on a **fresh daemon** (cold keeper warm-up measured once),
then cells of 1/5/20 concurrent sessions, then teardown: RSS retention at
10/30/60 s after all sessions close, daemon stop, orphan scan.

Per cell: attach latency (initialize RTT), base-file readiness (the didOpen
race guard — a cheap query against a base file must complete before overlay
install; the protocol has no view-ready signal), first overlay result
(didOpen → session-unique symbol visible), warm p50/p95 for
definition/references/rename/workspace-symbol, isolation violations, stalls.

Stalls: any request outstanding > 1 s triggers one 2 s stack sample of the
daemon (`/usr/bin/sample`, deduplicated, capped at 40/run) so stalls can be
attributed to `sync_session_overlay` / `rebuild_overlay_inputs` / salsa.
Stalled requests are recorded, never retried in a loop.

Known platform trap: on macOS the daemon socket lives under `$TMPDIR`; the
default per-user TMPDIR exceeds `sun_path` (SUN_LEN), so the harness forces a
short `--tmpdir /tmp/anlzb` for the daemon and every session.

## Worktrees

`disjoint`/`storm`/`manifest` sessions and the distant branch get real git
worktrees (branches `bench/*` in the subject clone) whose committed contents
are byte-identical to the overlay texts (asserted at prepare time).
`same_file` is inherently overlay-only: one path, N divergent versions.

## Output

- `bench/results/<scenario>.json` — raw records, RSS/status timelines, stalls
- `bench/results/samples/*.txt` — daemon stack samples captured during stalls
- `bench/results/meta.json` — versions, subject revision, host
- `bench/REPORT.md` — generated by `python3 bench/gen_report.py`
